# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Mover — приложение под Windows, не дающее заблокироваться экрану: через случайные
промежутки времени оно двигает курсор. Окно на fyne, иконка в трее, автозапуск.
Подробности назначения и настроек — в `README.md`.

## Команды

```sh
make help        # список целей
make build-win   # релизный mover.exe: иконка, версия, манифест, -H=windowsgui
make build       # отладочный mover-debug.exe с консолью
make run         # go run ./cmd/mover -debug
make check       # go vet + тесты
make lint        # golangci-lint (v2.12.x, конфиг .golangci.yml)
make icon        # перерисовать иконки в assets/ (вручную, результат коммитится)
```

Тесты:

```sh
go test -count=1 ./...                                  # все
go test -count=1 -run TestNoTickAfterStop ./internal/jiggler/   # один тест
go test -race -count=1 ./...                            # с детектором гонок
MOVER_HW_TEST=1 go test -run TestJiggle ./internal/mouse/ -v    # двигают реальный курсор
go test -run TestRenderVariants ./internal/ui/ -v       # рендер окна в %TEMP%\mover-*.png
```

**CGO обязателен** (fyne тянет OpenGL), и MSYS2 должен стоять в `PATH` **раньше**
`C:\Program Files\Git\mingw64\bin`: иначе `cc1.exe` подхватит старые
`libgmp-10.dll`/`libwinpthread-1.dll`, упадёт с `0xC0000139` и `go build` покажет
только `runtime/cgo: cgo.exe: exit status 2` — без единой подсказки о причине.
Makefile правит `PATH` сам; при вызове `go` напрямую нужен префикс
`PATH="C:\msys64\mingw64\bin;$PATH"`.

Первая сборка занимает ~4 минуты (компиляция GLFW/OpenGL через cgo), дальше секунды.

## Архитектура

Поток запуска (`cmd/mover/main.go`): `logging.Init` → `config.Load` →
`instance.Acquire` → `ui.Run` → цикл событий fyne.

### jiggler — единственный владелец состояния

`internal/jiggler` держит состояние в одной горутине, а `Start`/`Stop`/`Reconfigure`/
`Close` посылают ей команды по каналу и **ждут обработки**. Отсюда главный инвариант:
после возврата из `Stop` отложенный тик уже не сработает. Мьютексы сюда добавлять
не нужно — нужна новая команда. Наружу состояние отдаётся атомарным снимком
(`State()`) и колбэком `onState`.

Время абстрагировано интерфейсами `clock`/`timer`, поэтому тесты гоняют планировщик
на фейковых часах и не ждут реальных секунд.

### Правило потоков fyne

Начиная с fyne 2.6 обновлять виджеты из чужой горутины напрямую нельзя. Колбэк
`onState` и секундный тикер обратного отсчёта обёрнуты в `fyne.Do`. Любой новый
фоновый код, трогающий UI, обязан делать так же.

### Ловушка определения активности пользователя

Собственный вызов `SendInput` обновляет `GetLastInputInfo` ровно так же, как живой
пользователь. Поэтому `mouse.IdleMillis()` возвращает **пару** `(idle, ours)`:
второй флаг говорит, что последний ввод — наш инжект. Судить об активности только
по времени простоя нельзя, иначе система выглядит занятой всегда.

### mouse

Только `SendInput`; `SetCursorPos` не подходит принципиально — он не порождает
события ввода и таймер простоя не сбрасывает. Координаты **абсолютные**
(`MOUSEEVENTF_ABSOLUTE | MOUSEEVENTF_VIRTUALDESK`, нормировка в 0..65535):
относительный сдвиг проходит через ускорение мыши и может округлиться в ноль.
Раскладка `INPUT`/`MOUSEINPUT` закреплена тестом, `cbSize` берётся только через
`unsafe.Sizeof`.

`KeepAwake` (`SetThreadExecutionState`) действует на конкретный поток ОС, а горутины
Go мигрируют между потоками — поэтому состоянием владеет отдельная горутина,
прибитая к потоку через `runtime.LockOSThread`.

### autorun

Источник истины — реестр `HKCU\...\Run`, не `config.yml`. Один переключатель в трее
включает и автозагрузку, и автостарт таймера. Путь пишется в кавычках с флагом
`-autostart`; по этому флагу приложение стартует сразу в трей, без показа окна.

### Окно и трей (`internal/ui`)

- Крестик и «свернуть» **прячут** окно (`Hide`), а не закрывают: fyne завершает
  приложение, когда закрыто последнее окно, а скрытое остаётся в списке живых.
  Реальный выход — только пункт «Закрыть».
- **Флаг `windowVisible` должен совпадать с реальностью**: показывать окно
  только через `showWindow`, прятать — через `hideToTray`. По нему решает логика
  блокировки: окно, ошибочно считающееся видимым, после разблокировки само
  вернётся на экран.
- **Не вызывать `desk.SetSystemTrayWindow`**: он подменяет перехват крестика
  на голый `Hide` и по клику показывает окно в обход `showWindow`. Левый клик
  по иконке подключён напрямую через `systray.SetOnTapped`.
- События «окно свернули» у fyne нет, поэтому `minimize_windows.go` опрашивает
  `IsIconic` раз в 300 мс. Своё окно ищется через `EnumWindows` со сверкой PID —
  по одному заголовку ненадёжно.
- **Не вызывать `CenterOnScreen()`**: внутри fyne это уходит в
  `glfw.Monitor.GetVideoMode`, который разыменовывает nil при пустом списке
  мониторов (заблокированный сеанс) и роняет приложение.
- **Меню трея нельзя пересобирать на каждое изменение состояния.** Точечно менять
  пункт fyne не умеет: `SetSystemTrayMenu` сбрасывает меню через
  `systray.ResetMenu`, создаёт все пункты заново и заводит на каждый горутину.
  При этом `TrackPopupMenu` держит поток systray, пока меню открыто, а доставка
  нажатия — неблокирующая отправка в канал (`select` с `default`), то есть
  нажатие в момент пересборки теряется. Поэтому «Запустить» и «Остановить»
  всегда доступны (обе команды идемпотентны), состояние показывает иконка,
  а `rebuildTrayMenu` вызывается только по явному переключению автозапуска
  и с задержкой — чтобы всплывающее меню успело закрыться.
- Иконку трея нельзя задавать до старта цикла событий («tray not ready yet»),
  поэтому первое значение приходит из `fyneApp.SetIcon`.
- **Блокировка сеанса.** Пока окно видимо, fyne рисует его в OpenGL; за часы
  работы с погашенным экраном контекст «протухает», и после разблокировки окно
  не отзывается. `session_windows.go` ловит блокировку через `OpenInputDesktop`
  и на это время прячет окно — `decideRepaint` пропускает невидимые окна,
  и рисование прекращается. Обратный отсчёт по той же причине не обновляется,
  пока окно скрыто.
- Тема (`theme.go`) сама следует светлому/тёмному оформлению Windows: fyne передаёт
  вариант в `Color()`.

### Пути к файлам

`internal/apppath` кладёт `config.yml` и `app.log` рядом с exe, а при отсутствии
прав на запись — в `%APPDATA%`/`%LOCALAPPDATA%`. Каталог берётся от `os.Executable`,
**не** от рабочего каталога: из автозагрузки и из трея он совсем другой.

### Диагностика в релизной сборке

С `-H=windowsgui` у процесса нет stderr. Поэтому `logging.Init` вызывается самым
первым, `main` обёрнут в `recover`, а фатальные ошибки до появления окна
показываются через `ui.Fatal` (MessageBoxW напрямую).

Журнал по умолчанию молчит: уровень `Warn`, а файл создаётся лениво, при первой
записи (`lazyFile`), — в каталоге с программой не должно заводиться пустых
`app.log`. Флаг `-debug` понижает уровень до `Debug` и дублирует вывод в stdout.
Из этого следует: **на уровне Info писать бесполезно** для боевой диагностики —
то, что действительно важно увидеть у пользователя, должно быть `Warn`
или `Error`.

## Соглашения

- **Только Windows.** Платформозависимые файлы называются `*_windows.go` и несут
  `//go:build windows`. `internal/ui` импортирует `internal/mouse`, поэтому тоже
  windows-only.
- **Комментарии, сообщения логов и строки интерфейса — на русском.** Комментарий
  объясняет причину решения, а не пересказывает код.
- Линтер требует комментарии к пакетам и экспортированным символам
  (`revive: exported`, `package-comments` включены).
- `LazyProc.Call` всегда возвращает не-nil error — судить о результате нужно
  по `r1`; в `.golangci.yml` этот вызов исключён из `errcheck`.
- Иконки в `assets/` **генерируются и коммитятся**; `build-win` их не перерисовывает,
  для этого есть отдельная цель `make icon`.

## Ресурсы Windows в exe

`goversioninfo -64` собирает `resource.syso` из `cmd/mover/versioninfo.json`, и
`go build` подхватывает его по факту наличия в каталоге пакета `main`. Два подвоха:
флаг `-64` обязателен (по умолчанию генерируется 32-битный ресурс), а манифест
подключается **только** через `"ManifestPath"` — блока `"Manifest"` в goversioninfo
1.5.0 не существует, и написанный он молча игнорируется.

## Проверка интерфейса без экрана

Скриншот работающего окна снять не всегда возможно (OpenGL-поверхность не попадает
в GDI-захват, а в сессии без интерактивного рабочего стола `GetCursorPos` и
`SendInput` отвечают `Access is denied`). Вёрстка проверяется headless-рендером:
`internal/ui/render_test.go` рисует окно программным рендерером fyne в четырёх
сочетаниях «тема × состояние» и складывает PNG в `%TEMP%` — их можно открыть
и посмотреть.
